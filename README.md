# 充电桩 SLO 管理平台

TypeScript 全栈,零运行时依赖(Node 内置 `node:http` + `node:sqlite`,前端原生 TS + 手写 SVG)。
面向充电桩运营场景:几十个后台服务、每天几百条告警导致值班麻木、发布凭感觉。平台用 SLO + 错误预算把"该不该告警、能不能发版"变成可计算的决策。

## 快速开始

```bash
npm install
npm run simulate   # 生成半年回放数据:30 服务 × 181 天 × 5 分钟桶(156 万行)+ 16 个标注故障
npm run evaluate   # 评估回放:8 组正确性检查(见下)
npm run dev        # http://localhost:3000
npm run reset      # 删库重建(改了 SLO 目标/阈值后需要,种子数据建库时写入)
```

页面:服务目录 / SLO 定义 / 错误预算 / 告警 / 发布闸门 / 依赖关系图。

## 数据流水线

```
sim/generate.ts   请求回放:逐请求(3 个校验服务,223 万行)→ 聚合成 5 分钟桶(全部 30 服务)
                  16 个标注故障(可用性/延迟/上游传导/指标缺口),标注含实际影响用户比例
                  8 个计划内维护窗口(5 分钟对齐,窗口内错误率略高)
eval/evaluate.ts  评估:MWMB 告警回放 + 固定阈值基线对比、发布闸门回放(每 2h 一次 + 故障中一次)
server/index.ts   API 与静态页,"当前时间" = 数据集中最新桶时刻
```

## 核心引擎(`src/slo/`)

| 文件 | 职责 |
|---|---|
| `window.ts` | 任意窗口 SLI 聚合:维护按时间比例剔除、缺口桶不计分母、覆盖率 <70% 判数据不足 |
| `rollup.ts` | 内存前缀和,窗口查询 O(1),语义与 `window.ts` 一致,供评估/回放高频调用 |
| `budget.ts` | 错误预算:剩余量、1h/6h/24h 燃烧率、耗尽预测(max(1h,6h) 燃烧率 × 672h 周期) |
| `alerting.ts` | MWMB 纯函数:fast-burn(6h/30min,BR≥6,critical)+ slow-burn(24h/2h,BR≥2,warning) |
| `stream.ts` | 告警状态机:0.85x 迟滞恢复 + 30min 冷却,防 flapping |
| `gate.ts` | 发布闸门:预算 < 20% 或有进行中 critical 告警则拦截;紧急发布必填理由并留痕 |
| `impact.ts` | 依赖传导:1-Π(1-cᵢ) 合成上游贡献,>0.5 标记"受上游影响" |
| `compliance.ts` | 周维度达标导出 CSV(UTC 周一对齐) |

## 六个 SLO 落地坑(都已修复并有评估覆盖)

1. **窗口未满判定**:自然月初/服务上线初期数据不足,不能直接判不达标 —— 覆盖率 <70% 返回 `insufficientData`,页面标"数据不足",闸门不拦。
2. **告警 flapping**:燃烧率在阈值线附近抖动会反复开关告警 —— 0.85x 迟滞恢复 + 30min 冷却。
3. **基线超允许线**:健康基线错误率若接近预算允许值,预算日常空耗、告警常态 firing —— 仿真基线压到允许值的 1/5,评估用"健康期不预测近期耗尽"守住。
4. **传导线性求和爆炸**:多个上游贡献线性相加会超过 100% —— 改用 1-Π(1-cᵢ) 合成。
5. **延迟阈值严于健康 p95**:阈值太严,健康服务也会"不达标" —— 阈值取健康 p99.9 之上的最小直方图边界。
6. **双重缩放**:维护剔除和缺口剔除不能对同一桶重复缩放 —— 维护按比例缩一次,缺口桶整体跳过。

另外两个评估中暴露并修复的问题:

- **自然月预算跳变**:月初预算瞬间回到 100% —— 自然月消耗按 `w·本月至今 + (1-w)·上月终值`(w = 已过天数/28)平滑,跨月连续(检查 4)。
- **闸门告警查询时间语义**:`resolved_at IS NULL` 只对数据末尾正确,历史时刻回放漏掉当时进行中的告警 —— 改为 `opened_at<=t AND (resolved_at IS NULL OR resolved_at>t)`。

## 评估基线结论(`npm run evaluate`)

- **窗口一致性**:909 个采样窗口,引擎聚合 vs 逐请求重算最大偏差 0(延迟阈值对齐直方图边界,聚合无损)。
- **告警质量**:MWMB 53 条 vs 固定阈值基线 4858 条(**降 98.9%**),8 个重大故障(影响 ≥10% 用户)零漏报,无标注外误报,25/40 分钟指标缺口不触发告警。
- **发布闸门**:1836 次发布回放拦截 62 次,拦截均有预算/告警依据,6 个重大故障进行中发布全被拦,健康期无误拦截;紧急发布填理由放行并留痕(理由/操作人/预算快照)。
- **预算连续**:17612 个采样点,自然月/滚动窗口切换最大跳变 0.92%。
- **耗尽预测**:故障中预测 2.9h vs 实际 1.0h(量级正确);健康期预测 >7 天或不耗尽。

## 关键设计决策

- **SLI 统一为好请求比**:可用性 = 非 5xx 占比;延迟 = 延迟 ≤ 阈值请求占比。两类 SLO 共用一套预算/燃烧率数学。
- **延迟阈值必须取自固定直方图边界**(`HIST_EDGES`),桶级聚合与逐请求重算才严格相等。
- **没数据 ≠ 故障**:缺口桶不进分子分母,只影响覆盖率;覆盖率不足不下结论。
- **预算周期基准统一 672h(28 天)**,自然月窗口的消耗速度也按此折算。
